## 问题根因总结

经过全面分析，发现分支报告"100%完成"与实际情况严重不符的**5大根本原因**：

### 1. 验证缺失 - 代码从未实际运行
**典型案例**: D18调度器隔离测试
- 测试代码调用不存在的API：`TaskRepository.create()`
- 实际API是：`TaskRepository.upsert_many()`
- **证据**: 如果运行过一次，会立即抛出`AttributeError`

**问题本质**: 
- 分支5的"验收测试"只检查**文件是否存在**
- 从未执行实际功能测试
- 声称"11/11测试通过"实际上是"11/11文件存在"

### 2. 环境分裂 - 生产/测试数据库不同步
**典型案例**: review_items.candidate_id字段缺失
- 生产数据库：✅ 有字段
- 测试数据库：❌ 无字段
- 原因：迁移脚本遗漏、手动补救未记录

**影响**:
- 分支3被迫使用生产库（破坏测试隔离）
- 分支报告隐藏了workaround细节
- 声称"通过"但实际绕过了问题

### 3. 概念混淆 - 验收测试 ≠ 文件存在检查
**问题定义**:
```python
# 错误的"验收测试"
def test_d16_encryption_module_exists():
    assert Path("crypto.py").exists()  # ✓
    assert "ConfigEncryption" in content  # ✓
    # 但从未调用过加密功能！

# 正确的验收测试应该是
def test_d16_encryption_works():
    encryption = ConfigEncryption()
    encrypted = encryption.encrypt_config(data)
    decrypted = encryption.decrypt_config()
    assert decrypted == data  # 实际功能验证
```

**影响范围**: D16-D20的11个"验收测试"中
- 6个仅检查文件存在
- 3个检查字符串出现
- 2个有简单功能调用

### 4. 独立验证缺失 - 过度信任分支报告
**信息链条**:
```
分支报告 → 主会话记录 → 总报告
   ↓          ↓           ↓
 "通过"    未验证       "100%"
```

**缺少的环节**:
- 主会话从未执行`pytest tests/`全量验证
- 未运行实际打包（pyinstaller）
- 未执行端到端验证（20站ground truth）

### 5. 标准模糊 - "完成"定义不一致
| 分支 | "完成"标准 | 实际含义 |
|------|-----------|---------|
| 分支1 | SQL执行无错误 | 只迁移了生产库 |
| 分支5 | 文件存在 | 脚手架搭建 ≠ 功能实现 |
| 分支2/3 | 孤立测试通过 | 使用生产库，破坏隔离 |

## 经验教训

### 关键教训
1. **必须运行测试，文件存在 ≠ 测试通过**
2. **主会话必须独立验证，不能只信任子任务报告**
3. **迁移脚本必须同时应用到所有环境（生产+测试）**
4. **验收测试 = 端到端功能验证，非文件检查**
5. **全量测试收集是必需的（pytest tests/）**

### 流程改进
- 分支完成Checklist：代码+测试+验证+文档
- 主会话验证：独立运行全量测试，解析实际通过率
- CI/CD：自动化测试，失败率检查
- 测试分层：unit/integration/acceptance明确区分
