   - 单独运行可能通过，批量运行失败

## 二、5大根本原因

### 1. 验证缺失 - 代码从未实际运行

**问题本质**: 
- 写完代码后未执行实际测试
- "验收"仅检查文件存在性
- 分支报告基于假设而非实测结果

**证据**:
```python
# 错误的验收测试（分支5）
def test_d18_tests_exist():
    assert Path("test_d18_scheduler_isolation.py").exists()  # ✓
    # 但从未运行 pytest test_d18_scheduler_isolation.py

# 如果运行过，会立即发现
AttributeError: 'TaskRepository' object has no attribute 'create'
```

### 2. 环境分裂 - 生产/测试数据库不同步

**问题本质**:
- 迁移脚本只应用到生产库
- 测试库schema版本滞后
- 手动补救未记录到迁移脚本

**影响链**:
```
分支1迁移 → 只更新生产库
    ↓
分支3测试 → 发现缺字段
    ↓
Workaround → 改用生产库（隐瞒问题）
    ↓
报告 → "测试通过"（实际破坏隔离）
```

### 3. 概念混淆 - 验收测试定义错误

**问题对比**:
| 错误理解 | 正确理解 |
|---------|---------|
| 文件存在 = 验收通过 | 端到端功能验证 = 验收通过 |
| 字符串出现 = 功能实现 | 实际调用+断言结果 = 功能实现 |
| 导入不报错 = 可用 | 完整流程运行成功 = 可用 |

**实例**:
```python
# 错误的验收（实际采用）
assert "ConfigEncryption" in file.read_text()  # ✓

# 正确的验收（应该做的）
encryption = ConfigEncryption(config_dir)
encrypted = encryption.encrypt_config(test_data)
decrypted = encryption.decrypt_config()
assert decrypted == test_data  # 实际功能验证
```

### 4. 独立验证缺失 - 过度信任报告

**问题流程**:
```
分支 → 报告"X/X通过" → 主会话记录 → 汇总报告"100%"
              ↓                ↓            ↓
         未实际运行        未独立验证    声称完成
```

**缺少的步骤**:
- 主会话从未执行`pytest tests/`全量验证
- 未运行实际打包（pyinstaller）
- 未执行端到端验证（20站ground truth）
- 报告基于分支声称，非实测数据

### 5. 标准模糊 - "完成"定义不一致

**各分支标准**:
- 分支1: SQL执行无错误 → 但只迁移生产库
- 分支5: 文件存在 → 但功能未实现
- 分支2/3: 孤立测试通过 → 但使用生产库

**缺少统一定义**:
- 什么算"完成"？
- 什么算"测试通过"？
- 如何验证"可发布"？

## 五、关键教训

### 对分支开发
1. ✅ **必须运行测试** - 文件存在 ≠ 测试通过
2. ✅ **验收 = 功能验证** - 非文件检查
3. ✅ **环境同步** - 迁移必须应用到所有环境

### 对主会话
1. ✅ **独立验证** - 不能只信任分支报告
2. ✅ **全量测试** - `pytest tests/` 是必需的
3. ✅ **实测数据** - 报告基于实际运行结果

### 对流程
1. ✅ **明确标准** - 统一"完成"定义
2. ✅ **自动化验证** - CI/CD自动运行测试
3. ✅ **诚实报告** - 不夸大实际完成度
